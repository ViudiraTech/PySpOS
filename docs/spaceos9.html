SpaceOS 9

内核是 Rust 写的 SpaceKernel 3.0，实现了 Linux 64 位 ABI，目标是让现成的 Linux 程序直接运行。目前验证过的是 musl 动态链接的 BusyBox。镜像是 x86_64 的可启动 ISO。

  • Linux ABI

  • FAT32 根盘

  • BusyBox ash

内核自测、三个架构的编译检查和 QEMU 启动已经通过；用户态和驱动覆盖还在补。下载前请读使用声明。

启动顺序

在 QEMU / UEFI 上的启动流程，每一步对应镜像里的一个组件。

  1. 1

    UEFI 固件

    QEMU 里由 OVMF 提供，从 ISO 启动引导程序。

  2. 2

    Limine

    引导内核，并把 FAT32 的 rootfs 作为模块交给它。

  3. 3

    SpaceKernel 3.0

    初始化后只读挂载根盘，再启动 PID 1。

  4. 4

    systemg

    作为 PID 1，按依赖顺序启动 .service 里定义的服务。

  5. 5

    ash

    控制台 shell。退出后由 systemg 重新拉起。

组成

SpaceOS 9 没有另造一套用户接口，而是尽量把 Linux 现有的进程、文件和终端语义做完整，让现成程序能直接运行。

内核SpaceKernel 3.0。Rust、soft-float、多架构，x86_64 优先。
ABILinux 64 位：ELF / PIE / PT_INTERP、系统调用、信号、futex、epoll、AF_UNIX。
根盘FAT32。Limine 模块提供 rootfs，只读挂载；有 /dev、/proc、/sys、/tmp、/run。
PID 1systemg：服务单元、依赖排序、SIGCHLD 回收与重启。
用户态splibc（freestanding C 库）、sh、systemg。动态链接的 BusyBox 通过 musl 运行。
终端ash，带作业控制：raw termios、poll、控制终端、前台进程组、Ctrl-C / Ctrl-Z。

这一版新增的部分

  • VFS 缓存

    Linux 语义的 dentry / inode 缓存：正、负 dentry，inode 身份，LRU 回收，路径前缀失效。procfs、sysfs、devtmpfs 每次都重新验证，避免设备注销后还查到旧目录。FAT32 的大文件读取另外做了簇链缓存。

  • 动态链接与 BusyBox

    内核装载 ELF 解释器和 PIE。镜像里有 musl 动态加载器和 BusyBox standalone shell；ash 能接收键盘和串口输入，并执行 applet。

  • 进程、信号与终端

    clone 线程、进程组与会话、wait4 / waitid、POSIX 信号、futex、epoll、signalfd、timerfd、AF_UNIX。终端支持控制终端、前后台进程组和 raw 模式。

  • 从 PID 1 到 shell

    systemg 作为 PID 1，解析 /etc/systemg/*.service，按依赖启动服务、回收孤儿进程，并拉起控制台 shell。splibc 提供静态 C 运行环境和自带的 sh。

验证情况

范围状态内容
x86_64已验证UEFI/QEMU 启动、systemg 作 PID 1、BusyBox 动态加载、ash 交互、uname / id / nproc / ls / cat、VFS dcache 自测、SELFTEST_OK，以及三个架构的 cargo check。
aarch64 / riscv64仅编译检查内核能通过编译检查。用户态、rootfs 和启动链路没有在这个镜像里验证。
真实硬件与 GPU未验证目前只在 QEMU 的 VirtIO GPU 2D 上验证。真实 GPU、音频、网络、睡眠唤醒不在这个镜像的承诺范围内。
