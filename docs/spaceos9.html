概览

内核、ABI 与用户态

SpaceOS 9 的目标不是另造一套用户接口，而是尽量把 Linux 现有的进程、文件与终端语义实现完整，让现成程序能直接跑起来。

内核
SpaceKernel 3.0

Rust、soft-float、多架构；x86_64 优先

ABI
Linux 64-bit

ELF/PIE/PT_INTERP、syscall、信号、futex、epoll、AF_UNIX

根盘
FAT32

Limine 模块 rootfs、只读挂载、/dev /proc /sys /tmp /run

PID 1
systemg

服务单元、依赖排序、SIGCHLD 回收与重启

用户态
splibc

freestanding C 库、sh、systemg；动态 BusyBox 通过 musl 运行

终端
ash + job control

raw termios、poll、控制终端、前台进程组、Ctrl-C / Ctrl-Z

实现

这一版真正做了什么

  • VFS dentry / inode cache Linux 语义

    正/负 dentry、inode 身份、LRU 回收、路径前缀失效；procfs/sysfs/devtmpfs 强制重新验证，避免设备注销后仍查到旧目录。FAT32 大文件读取同时做了簇链缓存。

  • 动态链接与 BusyBox PT_INTERP

    内核装载 ELF 解释器与 PIE；镜像内提供 musl 动态加载器和 BusyBox standalone shell。ash 可以真正接收键盘/串口输入，并执行 applet。

  • 进程、信号与终端 Linux ABI

    clone 线程、进程组/会话、wait4/waitid、POSIX 信号、futex、epoll、signalfd、timerfd、AF_UNIX；终端支持控制终端、前后台组与 raw 模式。

  • 从 PID 1 到 shell systemg

    systemg 作为 PID 1 解析 /etc/systemg/*.service，按依赖启动服务、回收孤儿进程，并拉起控制台 shell；splibc 提供静态 C 运行环境与自带 sh。

验证边界

哪些验证过，哪些还没有

这里只写实际跑过的结果；未验收的部分明确标注，不用占位值冒充。

  • x86_64 实跑 已验收

    UEFI/QEMU 启动、systemg PID 1、BusyBox 动态加载、ash 交互、uname/id/nproc/ls/cat、VFS dcache 自测、SELFTEST_OK 与三架构 cargo check。

  • aarch64 / riscv64 仅编译检查

    内核可通过编译检查；用户态、rootfs 与启动链路尚未在该镜像中验收。

  • 真实硬件与 GPU 未验收

    当前验证在 QEMU 的 VirtIO GPU 2D 链路完成；真实 GPU、音频、网络与睡眠唤醒等未纳入本镜像承诺。
