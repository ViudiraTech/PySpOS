配置要求

PySpOS 是跑在宿主系统上的 Python 程序；SpaceOS 8 和 9 是要自己启动的内核。条件差别大，所以按产品分开写。

PySpOS 3.2.0

纯用户态，不直接操作硬件，能跑 Python 的机器就能跑。

Python3.10 或更高。CI 覆盖 3.10、3.12、3.14。
系统Windows 7 及以上、Linux 各发行版、macOS。
磁盘约 120 MB。不需要管理员权限。
CPU / 内存双核 CPU、512 MB 内存足够，不需要独立显卡。
终端curses 的首次开机向导需要 80×24 字符的终端。SSH、tmux、Windows Terminal 都可以。
可选依赖unicorn（ELF 引擎，缺失时退回自研模拟器）；tzdata（真实时区，Windows 和精简容器镜像需要）。都不是硬性要求。

SpaceOS 9 公开预览

目前只在 QEMU 上验证过。

虚拟机x86_64 QEMU，推荐 Q35 机型和 VirtIO GPU 2D。
固件OVMF UEFI 固件。
内存至少 512 MiB。
未验证真实硬件、真实 GPU、音频、网络、睡眠唤醒。
其他架构aarch64 / riscv64 只通过编译检查，镜像里没有它们的用户态。

SpaceOS 8

请用可抛弃的机器和测试盘

NTFS 写入驱动目前还不能信任，确认稳定前不要让它碰重要数据。已在 Dell PowerEdge R410 等实体服务器上验证。

表里“已验证”是实际跑过的组合，“默认关闭”的需要自己在 make menuconfig 里打开。

硬件要求状态
处理器x86_64 必需。多核可用，SMP 启动会拉起全部核心，并在核间迁移任务、均衡负载。已验证
内存最低 128 MB，512 MB 可启动。跑图形桌面并使用 swap，建议 1 GB 以上。
固件经 Limine 引导，UEFI 与 Legacy 两种模式都支持，不挑固件实现。UEFI 已验证
输入PS/2 键盘和鼠标是主路径，提供 Linux 兼容的 evdev；另支持 USB HID（键盘、鼠标、消费类控制器）。PS/2 路径仍在验证中。xHCI USB HID 已验证
显示DRM/KMS 内核核心、通用 GPU 驱动注册表、内置 VirtIO-GPU 驱动；GOP 帧缓冲控制台（点阵字体）和软件帧缓冲兜底。没接显卡时可用 GOP 文本控制台。真实 GPU 驱动未完成
存储IDE/ATA、AHCI（SATA）、NVMe、USB Mass Storage 都有驱动（NVMe 已启用）。默认根文件系统是 tmpfs。NTFS 写入不建议用
网络需要 Intel e1000 / e1000e 或 Realtek RTL8139 / RTL8169。协议栈自研，客户端带 DHCP。其他网卡可能无法联网。需要指定网卡
音频（可选）Sound Blaster 16 与 Intel HD Audio，带 ALSA 兼容的 PCM / control ABI。SB16 需要在 menuconfig 里打开。SB16 默认关闭

构建

必需：make、gcc（建议 13.3+）、qemu、xorriso。建议：clang-format、clang-tidy。只有 menuconfig 需要 kconfig-frontends 和 libncurses-dev。

sudo apt install build-essential qemu-system-x86 xorriso libncurses-dev

默认关闭的功能

有些子系统在 Kconfig 里默认是 n，要用得自己打开：VIRTIO / VIRTIO_GPU（虚拟化设备）、SOUND_SB16（声卡）。用 make menuconfig 打开，并确认虚拟机或实体机上有对应设备。新增 GPU 驱动，是在 drivers/gpu/gpu_drivers.c 的注册表里加一条记录。
