配置要求

跑起来需要什么

SpaceOS 系列三个产品的运行条件差别很大—— PySpOS 是跑在宿主系统上的 Python 程序，SpaceOS 8 是要独占机器的真内核。 所以这里按产品分开列，不做一张通用表。

PySpOS 3.2.0

模拟操作系统

软件要求

持续维护
  • Python 3.10 或更高（CI 覆盖 3.10 / 3.12 / 3.14）
  • 操作系统：Windows 7+、Linux 各发行版、macOS
  • 磁盘约 120 MB
  • 无需管理员权限，除部分终端功能外均可普通用户运行

可选依赖：unicorn（ELF 引擎，缺失自动降级到自研模拟器）、 tzdata（真实时区，Windows 与精简容器镜像需要）。 两者都不是硬性要求。

PySpOS 详情 下载

硬件要求

PySpOS 是纯用户态程序，不直接操作硬件， 因此基本没有硬性门槛——能跑 Python 的机器就能跑。

双核 CPU 足够 512 MB 内存足够 无需独立显卡

唯一与显示相关的是终端：使用 curses 的 OOBE 向导需要 一个能承载 80×24 字符的终端。SSH、tmux、ConEmy、 Windows Terminal 都可以。

SpaceOS 8

真实内核

这一部分是硬要求。下面标注「已验证」的是我们实际跑过的组合， 标注「默认关闭」的需要自己在 make menuconfig 里打开。

请用可抛弃的机器与测试盘

NTFS 写入驱动目前尚未被认为可以信任。在确认它稳定之前， 不要让它碰到重要数据。已在 Dell PowerEdge R410 等实体服务器上验证。

处理器

x86_64 必需。多核可用，SMP 启动会拉起全部核心 并在核间做任务迁移与负载均衡。
已验证

内存

最低 128 MB。要跑图形桌面并使用 swap， 建议 1 GB 以上。
512 MB 可启动

固件

通过 Limine 引导，UEFI 与 Legacy 两种模式都支持， 不挑固件实现。
UEFI 已验证 Legacy 支持

输入设备

PS/2 键盘与鼠标为主路径，提供 Linux 兼容的 evdev；另支持 USB HID （键盘、鼠标、消费类控制器）。
PS/2 路径验证中

显示

DRM/KMS 内核核心，带通用 GPU 驱动注册表， 内置 VirtIO-GPU 驱动；另提供 GOP 帧缓冲控制台（带点阵字体）与软件帧缓冲兜底。 未接显卡时可用 GOP 文本控制台。
真实 GPU 驱动未完成

存储

IDE/ATA、AHCI（SATA）、NVMe、USB Mass Storage 均有驱动。默认根文件系统是 tmpfs。
NVMe 已启用 NTFS 写入不建议用

网络

需要 Intel e1000 / e1000e 或 Realtek RTL8139 / RTL8169 网卡。 协议栈自研，客户端带 DHCP。
非该网卡可能无法联网

音频（可选）

Sound Blaster 16 与 Intel HD Audio， 带 ALSA 兼容的 PCM / control ABI。
SB16 默认关闭，需 menuconfig 打开

构建工具链

必需：make、gcc（建议 13.3+）、 qemu、xorriso

建议：clang-format、clang-tidy （格式化与静态分析）

仅 menuconfig 需要： kconfig-frontends 与 libncurses-dev

Debian / Ubuntu：
sudo apt install build-essential qemu-system-x86 xorriso \ libncurses-dev

默认关闭的功能

有些子系统在 Kconfig 里默认是 n， 想用得自己打开：

  • VIRTIO / VIRTIO_GPU —— 虚拟化设备
  • SOUND_SB16 —— Sound Blaster 16 声卡

用 make menuconfig 打开，然后确认你的虚拟机或实体机 上确实有对应设备。新增 GPU 驱动的方式是在 drivers/gpu/gpu_drivers.c 的注册表里加一条记录。
