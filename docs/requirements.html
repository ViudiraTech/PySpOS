PySpOS 3.2.0

模拟操作系统：能跑 Python 就行

  • 软件要求 维护中

    Python 3.10 或更高（CI 覆盖 3.10 / 3.12 / 3.14）。系统：Windows 7+、Linux 各发行版、macOS。磁盘约 120 MB。无需管理员权限。

    可选依赖：unicorn（ELF 引擎，缺失自动降级到自研模拟器）、tzdata（真实时区，Windows 与精简容器镜像需要）。都不是硬性要求。

    PySpOS 详情 → · 下载

  • 硬件要求 纯用户态，没有硬性门槛

    不直接操作硬件，能跑 Python 的机器就能跑：双核 CPU、512 MB 内存足够，无需独立显卡。

    唯一与显示相关的是终端：curses 的 OOBE 向导需要一个 80×24 字符的终端。SSH、tmux、Windows Terminal 都可以。

SpaceOS 8

真实内核：这是硬要求

标注“已验证”的是实际跑过的组合，标注“默认关闭”的需要自己在 make menuconfig 里打开。

!

请用可抛弃的机器与测试盘

NTFS 写入驱动目前尚未被认为可以信任。在确认稳定之前，不要让它碰重要数据。已在 Dell PowerEdge R410 等实体服务器上验证。

  • 处理器 x86_64 必需 · 已验证

    多核可用，SMP 启动会拉起全部核心，并在核间做任务迁移与负载均衡。

  • 内存 最低 128 MB · 512 MB 可启动

    要跑图形桌面并使用 swap，建议 1 GB 以上。

  • 固件 UEFI 已验证 · Legacy 支持

    经 Limine 引导，UEFI 与 Legacy 两种模式都支持，不挑固件实现。

  • 输入 xHCI USB HID 已验证

    PS/2 键盘与鼠标为主路径，提供 Linux 兼容的 evdev；另支持 USB HID（键盘、鼠标、消费类控制器）。PS/2 路径仍在验证中。

  • 显示 真实 GPU 驱动未完成

    DRM/KMS 内核核心，通用 GPU 驱动注册表，内置 VirtIO-GPU 驱动；GOP 帧缓冲控制台（带点阵字体）与软件帧缓冲兜底。未接显卡时可用 GOP 文本控制台。

  • 存储 NTFS 写入不建议用

    IDE/ATA、AHCI（SATA）、NVMe、USB Mass Storage 均有驱动（NVMe 已启用）。默认根文件系统是 tmpfs。

  • 网络 需要指定网卡

    需要 Intel e1000 / e1000e 或 Realtek RTL8139 / RTL8169。协议栈自研，客户端带 DHCP。非该网卡可能无法联网。

  • 音频（可选）SB16 默认关闭

    Sound Blaster 16 与 Intel HD Audio，带 ALSA 兼容的 PCM / control ABI。SB16 需 menuconfig 打开。

构建

工具链与默认关闭的功能

  • 构建工具链

    必需：make、gcc（建议 13.3+）、qemu、xorriso。建议：clang-format、clang-tidy。仅 menuconfig 需要 kconfig-frontends 与 libncurses-dev。

    sudo apt install build-essential qemu-system-x86 xorriso libncurses-dev
  • 默认关闭的功能

    有些子系统在 Kconfig 里默认是 n，想用得自己打开：VIRTIO / VIRTIO_GPU（虚拟化设备）、SOUND_SB16（声卡）。用 make menuconfig 打开，并确认虚拟机或实体机上确实有对应设备。新增 GPU 驱动是在 drivers/gpu/gpu_drivers.c 的注册表里加一条记录。
